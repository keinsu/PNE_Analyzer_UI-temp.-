# Battery Analysis Studio v3.0 검증 보고서

검증일: 2026-11-18 (한국 시간)

## 검증 범위

이번 결과는 **합성 데이터와 로컬 Windows 환경에서의 검증**이다. 실제 PNE 장비 파일·제조사 기준 출력·회사 PC에서의 검증 완료를 의미하지 않는다. 바이너리 해독, 계산 호환성, 화면 조작, 실행파일 시작은 각각 구분해서 판단한다.

- 자동 기능 테스트: 최종 58개 테스트가 8.425초에 통과했다. 실행 로그는 `validation/unit_tests.log`에 보관했다. 성능 측정 직전에는 53개 테스트를 실행했으며 이후 Excel·CSV·PNG 저장과 권한 제한 폴더 처리 등 검증을 추가했다.
- 단일 Step의 기존 Qt Cycle 요약·dQ/dV·dV/dQ 기본값은 허용오차 `1e-12`로 비교했다.
- PNE 입력은 독립적으로 필드를 패킹한 합성 CYC, StepEnd와 ZIP 구조로 검증했다. 기존 Go 테스트 18개 통과 및 양 엔진 실행 비교(합성 6채널·979 Raw 행·72 Step)를 확인했다. 수치 18개 필드와 Step/Cycle/매칭 상태가 Go CSV 반올림 허용오차 안에서 일치했다. 상세 범위는 `go_comparison.md`와 `validation/go_comparison.json`에 기록했다.
- Qt 화면 통합 테스트는 ZIP 입력 → Summary → Raw → 미분 이동, 기준 Cycle/지표 유지, 프로젝트 설정·축·곡선 숨김 복원, 표 정렬 후 복사, 실제 원본 점 Hover를 확인한다.
- 분석 결과는 GUI 스레드에서 반영되는지 검사하고, 이전 작업 결과가 새로운 입력/조건을 덮지 않는지와 설정 변경 후 이전 결과가 저장 가능 상태로 남지 않는지를 검사한다.
- INITIAL/UNMATCHED 보존, REVIEW 기본 제외, Cycle 0과 미지정 Cycle -1의 구분, 수동 분할시험 연결의 원본 식별 정보 보존을 회귀 항목으로 관리한다.

## 소스 실행 점검

`validation/source_smoke.json` 기록은 Qt 6.11.1에서 창 생성, 합성 3개 채널 입력, Raw·Cycle 요약, 500점 미분, DCR 4개 Pulse, 프로젝트 저장·열기를 확인했다. `frozen:false`인 소스 실행 결과이므로 EXE 검증으로 대신 사용하지 않는다.

최종 Windows 배포 EXE도 `tests/verify_frozen.py`로 직접 실행했다. `validation/frozen_smoke.json`에서 `status:ok`, `frozen:true`, Qt 6.11.1, 합성 입력 3채널, 500점 미분, DCR 4개 Pulse와 프로젝트 저장·읽기 통과를 확인했다. 실행파일은 콘솔창이 없는 폴더형 배포이며, 충돌 원인이었던 Poppler ICU DLL 두 개가 배포 폴더에 없는 것도 확인했다. 이 보고서의 성능 수치는 Python 소스 실행 기준이다. 회사 PC에서의 실제 EXE 작동 확인은 별도이다.

## 성능 측정 환경과 입력 규모

측정 원문은 `validation/performance.json`, 실행 도구는 `tests/benchmark_workspace.py`이다.

- Windows 10 64비트, 논리 CPU 6개, RAM 15.94 GiB.
- Python 3.13.5, NumPy 2.2.6, pandas 2.3.0, Qt 6.11.1.
- Qt offscreen 환경에서 1366×768 창을 생성했다. 실제 화면 배율별 조작과 회사 PC GPU/화면 환경은 별도 검증 대상이다.
- 단일 채널: 100 Cycle × 충전/방전 각각 300점 = 60,000 Raw 레코드. 원본 약 10.6 MB, ZIP 약 1.46 MB.
- 다중 채널: 20채널 × 10 Cycle × 충전/방전 각각 300점 = 120,000 Raw 레코드. 원본 약 21.2 MB, ZIP 약 3.15 MB.
- 미분 표시: 100개 방전 곡선 × 500 보간점 = 50,000 계산점.

## 측정 방법과 확인된 개선

- 처리 시간은 `time.perf_counter`로 측정했다. 순수 계산과 실제 비동기 화면 흐름을 나누었다.
- GUI 이벤트 간격은 20 ms QTimer의 실제 호출 간격으로 측정했다. 데이터 처리가 별도 스레드에 있어도 결과를 화면에 대량 추가할 때는 GUI 지연이 발생할 수 있다.
- 최초 측정에서 Raw 표의 자동 정렬이 GUI를 약 21초 막는 문제를 발견했다. 전체 Raw에 대해 Qt가 Python 값을 반복 비교하던 구조를 pandas 정렬 구조로 수정한 후, 같은 60,000점 입력 흐름의 최대 이벤트 간격은 112 ms로 줄었다.
- 100개 미분 곡선을 여러 그래프에 동시에 준비하는 구간에서는 약 1.16초 이벤트 지연이 남아 있다. 일반 계산 시간과 구분해 기록하며, 더 많은 곡선/실제 데이터에서는 표시 작업 분할·필요한 탭만 준비하는 최적화 여지가 있다.
- Hover는 실제 그래프 범위 안의 좌표를 사용하고 계산점 읽기가 수행됐음을 확인한 뒤 30회 측정했다. 화면 바깥 좌표의 빠른 반환 시간을 검색 성능으로 사용하지 않았다.
- 메모리는 psutil의 RSS와 Windows Peak Working Set을 기록했다. Qt·Python·수치 라이브러리와 합성 자료 생성도 같은 프로세스에 포함되므로 순수 데이터 크기만을 나타내지 않는다.

## 남은 검증과 제한

1. 대표 실제 PNE 데이터에서 전압·전류·용량 원시값, StepEnd 연결, 초기 레코드와 재시작 Cycle을 장비 화면/기준 출력과 대조해야 한다.
2. DCR의 V0·휴지 전류·CC/CP 적용 전류·1s/10s/30s 보간값·Return 용량을 실제 시험과 대조해야 한다.
3. 제조사·장비 버전별 다른 CYC 프로필은 검증되지 않았다. 72B/176B는 역분석 프로필이며 제조사 규격 인증이 아니다.
4. 현재 입력 단계는 선택 채널의 전체 Raw DataFrame을 메모리에 읽는다. 캐시와 작업 취소가 완전한 지연 로딩을 의미하지 않는다.
5. 60,000/120,000점 검증을 수백만·수천만 레코드 시험의 성능 보증으로 확대하지 않는다. 최대 사용량 자료를 추가 측정해야 한다.
6. 합성 데이터를 이용한 EXE 점검과 회사 Windows PC에서 실제 자료를 사용하는 검증은 구분한다. 백신 예외 설정이나 백신 해제를 배포 전제로 삼지 않는다.
7. 과학적 피크 대응, 전압 기반 SOC 추정 등의 물리적 타당성을 자동 검증하는 프로그램은 아니다. 불확실한 값과 계산 실패는 추정값으로 조용히 대체하지 않는다.

## 재현

프로젝트 루트에서 다음을 실행한다.

```text
python -B -m unittest discover -s tests -v
python -B tests/benchmark_workspace.py --run-tests
python -B main.py --smoke-test validation/source_smoke.json
```

벤치마크는 임시 합성 자료와 임시 캐시를 사용한다. 원본 장비 파일은 읽거나 변경하지 않는다.
